providers.json

Token Eye 核心配置文件。定义所有监控平台的 API 端点、解析规则、告警阈值、显示样式和自适应配色。

适用于 macOS（SwiftBar）/ Linux（UKUI 托盘）/ Android（Glance 小部件）三端——三端读取同一份 schema。完整使用说明见 README。本页面更新至 v0.18.1（2026-09）。

3. colors — 自适应配色

colors 段定义浅色/深色模式的全局配色。脚本检测到外观后自动选用对应模式。内置兜底值，此段可选。

{
  "colors": {
    "dark": {
      "default":   "#ffffff",
      "secondary": "#aaaaaa",
      "muted":     "#888888",
      "header":    "#FFD60A",
      "ok":        "#56B4E9",
      "warn":      "#E69F00",
      "err":       "#CC79A7"
    },
    "light": {
      "default":   "#000000",
      "secondary": "#2c2c2e",
      "muted":     "#48484a",
      "header":    "#0066CC",
      "ok":        "#0072B2",
      "warn":      "#B86E00",
      "err":       "#8E1A4A"
    }
  }
}
字段适用界面位置色弱安全？
default所有未设 nameColor 的 provider 名称行、菜单项默认文字—
secondary子行描述文字（plan_usage 的"5小时窗口/周窗口/重置"）—
muted"上次更新" 时间戳、文件路径提示—
header下拉菜单顶部 "Token Eye" 标题行—
ok可用/正常状态文字（如 "可用"、"API Key 有效"、进度条 ≥20%）🟦 蓝
warn警告状态（如 "耗尽临近"、进度条 10-20%）🟧 橙
err错误状态（如 "不可用"、"API Key 无效"、进度条 <10%）🟪 紫红

配色哲学：使用了 Wong (2011) 色弱安全调色板，蓝/橙/紫红三种状态色在红绿色弱用户眼中能清晰区分。如果仍不满意，自由替换即可。

4. Provider 配置

每个 provider 对象定义了一个监控平台。

4.1 通用字段

字段类型说明
id 必填string平台唯一标识，如 deepseek
name 必填string显示名称，如 DeepSeek
keychainService 必填stringmacOS Keychain 中存储 API Key 的服务名，如 DEEPSEEK_API_KEY（Linux 对应 gnome-keyring）
enabledboolean设为 false 可临时禁用该平台，不删除配置
consoleUrlstring控制台跳转链接；详情菜单末尾显示「→ 打开 X 控制台」可点击项
cacheTtlnumber单 provider 缓存 TTL（秒），覆盖全局 cache 段
refreshParamstring鉴权错误时自动执行的刷新脚本名（如 refresh-mimo-cookie）；详情菜单出现「🔄 刷新 X Cookie」可点击项。注意：Android 版加载时剔除所有带此字段的服务商（Cookie 刷新无法移植）
refreshIntervalnumber主动续期周期（秒，≥60）：即使 Cookie 仍有效也按周期从浏览器复制最新 Cookie 到 Keychain，减少 401 触发面（仅对配置了 refreshParam 的服务商生效）
alertobject告警阈值配置，见 §6.3 alert 告警

4.2 api — API 请求配置

字段类型默认说明
url 必填string—API 端点 URL
methodstringGETHTTP 方法
authHeaderstringAuthorization认证头名称
authPrefixstringBearer 认证前缀（注意末尾空格）
headersobject—额外 HTTP 请求头，如 {"OpenAI-Organization": "org-xxx"}

Cookie 鉴权模式：部分平台（如 MiMo platform API）不用 Bearer Token，而要求请求头携带完整 Cookie 组合。配置 "authHeader": "Cookie" + "authPrefix": ""，Keychain 条目存完整 Cookie 串（name1=v1; name2=v2; ...）作为整个 Cookie 头发送。Cookie 为会话级，配合 refreshParam + refreshInterval 实现半自动刷新（401 自愈 + 主动续期 + 失效自动打开登录页）。

4.3 display — 显示配置

字段类型默认说明
unitstring—数值单位（菜单栏行），如 ¥、%
labelstring—状态标签（status parser），如 免费
nameColorhex 或 objectcolors.{theme}.default平台名称行强调色；支持深浅双套 {"dark":"#xxx","light":"#xxx"} 随系统外观切换
currencySymbolsobjectUSD→$，其余→¥货币代码 → 符号映射，如 {"USD":"$","EUR":"€","CNY":"¥"}

5. Parser 类型

三种 parser 对应不同 API 响应结构。

5.1 balance — 余额型

适用于返回余额信息的 API（如 DeepSeek、MiMo）。余额 + 今日消耗估算 + 预计可用天数 + 近 7 天消耗柱状。

{
  "type": "balance",
  "fields": {
    "balance": "balance_infos.0.total_balance",
    "currency": "balance_infos.0.currency"
  },
  "defaultMinBalance": 5.0
}
字段说明
balance. 分隔的 JSON 路径。数字 = 数组索引
currency货币字段路径。默认 CNY（→¥），USD→$，可用 display.currencySymbols 覆盖
alertThresholdfields.alertThreshold：指向 API 返回的告警阈值字段路径，平台有则自动读（优先级链最高级）
defaultMinBalance按 parser 类型兜底的余额告警阈值（优先级链最低级，无则不告警）

5.2 plan_usage — 用量型

适用于返回按模型分组的用量数据的 API（如 MiniMax）。双窗口（5h/周）进度条 + 重置倒计时。

{
  "type": "plan_usage",
  "arrayPath": "model_remains",
  "fields": {
    "model": "model_name",
    "intervalPct": "current_interval_remaining_percent",
    "intervalStatus": "current_interval_status",
    "weeklyPct": "current_weekly_remaining_percent",
    "weeklyStatus": "current_weekly_status",
    "intervalBoost": "interval_boost_permille",
    "weeklyBoost": "weekly_boost_permille",
    "resetMs": "remains_time"
  },
  "modelLabels": { "general": "M2.7/M3 通用", ... },
  "showModels": ["general", "video"],
  "windowLabels": { "interval": "5h", "weekly": "7d" },
  "pctDirection": "remaining",
  "barLength": 20
}
字段说明
model模型标识字段
intervalPct/weeklyPct百分比，0-100 整数
intervalStatus/weeklyStatus状态码：1=可用 2=耗尽临近 3=耗尽（仅旧接口兜底用，见下方说明）
intervalBoost/weeklyBoost限时加成（千分比，>1000 显示 🔥xN）
resetMs重置倒计时（毫秒）
windowLabels窗口显示名，默认 {"interval":"5h","weekly":"7d"}
pctDirectionremaining（默认）| used。进度条与告警阈值统一按「已用%」口径；源字段为剩余%的服务商（如 MiniMax）自动翻转，直接返回已用%的配 "used" 跳过翻转
barLength进度条长度，默认 20 格
statusMap状态码 → 文案映射，默认 {1:可用, 2:耗尽临近, 3:耗尽}

状态推导规则：接口返回百分比字段时优先按百分比推断状态（≥20% 可用 / 10–20% 耗尽临近 / <10% 耗尽，与图标阈值一致）；statusMap 仅在无百分比字段的旧接口生效，此时 total=0 显示「无套餐」。MiniMax 新接口的 total_count 字段已废弃（恒为 0），不能用于判断有无套餐。

5.3 status — 状态型

适用于只需验证 Key 有效性的 API（如 MiMo）。

{
  "type": "status",
  "okField": "object",
  "okValue": "list"
}
字段说明
okFieldJSON 路径，指向判断有效性的字段。留空则检查整个响应是否存在
okValue期望值。留空则只检查字段是否为非 null

6. 高级配置

6.1 cache — 缓存 TTL

按 parser 类型设置缓存 TTL（秒），命中缓存跳过 API 调用；失败请求 10s 内不重试。单个 provider 可用 cacheTtl 覆盖。

{
  "cache": {
    "balance": 300,
    "plan_usage": 30,
    "status": 60
  }
}

6.2 menuBar — 菜单栏汇总

默认菜单栏只显示 👁 图标。开启后显示关键数字汇总；也可传 id 数组只显示指定平台。

{
  "menuBar": {
    "showSummary: true          // 或 ["deepseek","mimo"]
  }
}

效果：👁 ¥13.5 | ✅ M2.7 92% | 免费。（Linux UKUI 托盘不支持文字汇总，只显示三态图标）

6.3 alert — 告警阈值

低阈值时推送系统通知（去重，恢复后自动清除标记并补发「已恢复」通知）。可在 provider 上配 alert，或在根 alerts 段按 id 配置。

{
  "id": "deepseek",
  "alert": {
    "minBalance": 5.0,      // balance：余额低于 5.0 告警
    "dailySpendMax": 20.0,   // balance：今日消耗超 20.0 告警（余额快照差值估算）
    "daysLeft": 7             // balance：预计可用天数低于 7 告警（按 24h 速率外推）
  }
}
{
  "alerts": {
    "minimax": { "minPct": 80 }   // plan_usage：已用% 超过 80 告警
  }
}

balance 阈值优先级链：API 字段（parser.fields.alertThreshold）> provider.alert.minBalance > parser.defaultMinBalance > 不告警。菜单栏状态图标与告警检查共用同一阈值。minPct 语义与进度条一致，按已用%方向判断（受 pctDirection 影响）。

通知默认带系统提示音（Glass）；环境变量 TOKEN_EYE_SOUND 换声音、TOKEN_EYE_NOTIFY=0 整体禁用。

7. 完整示例 — 添加新平台

{
  "id": "my-platform",
  "name": "My Platform",
  "keychainService": "MY_API_KEY",
  "api": {
    "url": "https://api.example.com/v1/usage",
    "method": "GET"
  },
  "parser": {
    "type": "balance",
    "fields": {
      "balance": "data.credits",
      "currency": "data.currency"
    }
  },
  "display": {
    "unit": " credits",
    "label": "剩余",
    "nameColor": "#30D158"
  }
}

配置完成后将 API Key 存入 Keychain：

$ security add-generic-password -s MY_API_KEY -a "" -w "sk-your-key"

SwiftBar 下次刷新时自动加载，无需修改脚本。页面自动保持 providers.json 同步，不依赖脚本内硬编码。
